# Excel 自动化综合项目

一个基于 Python、Pandas 和 OpenPyXL 的 Excel 数据自动化处理项目。

本项目以实际 Excel 数据处理场景为基础，将文件批量读取、字段标准化、数据清洗、去重审计、数据合并、异常检查、统计汇总和 Excel 格式化等常见操作进行模块化封装。

项目重点是探索如何将一次性的 Excel 数据处理代码逐步整理为具有一定复用能力的自动化处理框架。

## 项目目标

Excel 数据处理工作中存在大量重复操作，例如：

- 批量打开多个 Excel 文件
- 清理数据中的空格
- 统一金额格式
- 统一字段名称
- 合并多个文件
- 删除重复数据
- 检查异常数据
- 与主数据进行匹配
- 生成统计结果
- 调整最终 Excel 格式

因此，本项目尝试将这些通用操作提取出来，并通过：

```text
main.py
config.py
excel_tools.py
```

进行职责划分。

## 模块说明

### main.py

负责具体项目的业务流程：

- 调用 Excel 工具函数
- 组织数据处理流程
- 执行业务规则
- 生成统计结果
- 生成异常数据
- 输出最终 Excel 文件

### excel_tools.py

负责封装比较通用的 Excel/Pandas 数据处理功能，例如：

- Excel 文件批量读取
- 数据合并
- 数据清洗
- 重复数据处理
- 数据格式处理
- Excel 输出相关操作

### config.py

用于保存项目中的配置项和业务规则。

例如字段名称映射：

```python
COL_NAME_KEYWORD = {
    '订单编号': '订单号',
    '订单': '订单号',
    'SKU': '商品编号',
    '货号': '商品编号'
}
```

以及不同数据表之间的关联关系：

```python
MERGE_KEY_ON2 = {
    '商品主数据.xlsx': {
        'left_on': '商品编号',
        'right_on': '商品编号',
        'how': 'left'
    }
}
```

## 主要功能

### 1. 批量读取 Excel

通过 `pathlib` 遍历指定目录中的 Excel 文件，实现批量读取。

```text
Data/
├── 文件1.xlsx
├── 文件2.xlsx
├── 文件3.xlsx
└── ...
```

### 2. 数据清洗

包括：

- 去除字符串前后空格
- 金额字段格式转换
- 数值类型转换
- 日期字段处理
- 缺失值处理
- 异常值识别

例如：

```text
¥1,200.00
```

经过处理后转换为：

```text
1200.00
```

### 3. 表头标准化

不同来源的 Excel 文件可能使用不同的字段名称表示相同的数据。

例如：

```text
订单编号
订单号
订单
```

通过配置映射统一为标准字段。

```text
订单编号 ─┐
订单号   ─┼──→ 订单号
订单     ─┘
```

### 4. 多文件合并

将多个来源的数据统一后进行纵向合并：

```text
Excel 1
   │
Excel 2 ──→ 字段标准化 ──→ 数据清洗 ──→ 合并
   │
Excel 3
```

### 5. 去重与异常审计

项目没有简单地将重复数据直接删除，而是将正常数据和重复数据分开处理。

重复数据进入异常记录，正常数据继续参与后续统计。

### 6. 主数据关联

使用 Pandas `merge()` 将业务数据与主数据进行关联。

```text
业务数据
   │
   ├── 商品编号 ──→ 商品主数据
   ├── 门店编号 ──→ 门店主数据
   └── 人员编号 ──→ 人员主数据
```

关联规则通过配置文件管理。

### 7. 数据异常检查

对处理后的数据进行业务规则检查，例如：

- 必填字段为空
- 数量无法转换为有效数值
- 销售金额异常
- 订单编号格式异常
- 主数据匹配失败
- 数据重复

异常数据集中进入异常报告。

### 8. 数据统计

利用 Pandas 的 `groupby()` 对清洗后的数据进行分组汇总。

### 9. Excel 自动化输出

使用 OpenPyXL 对最终 Excel 文件进行进一步处理，包括：

- 创建工作表
- 设置标题
- 合并单元格
- 调整列宽
- 设置筛选
- 冻结窗格
- 设置时间格式
- 设置数字格式

## 配置驱动设计

项目中的一个重要思路是：

> 将经常变化的内容放到配置文件中，将相对稳定的处理逻辑封装到工具模块中。

例如字段标准化：

```python
COL_NAME_KEYWORD = {
    '订单编号': '订单号',
    '订单': '订单号',
    'SKU': '商品编号',
    '货号': '商品编号'
}
```

以及数据关联：

```python
MERGE_KEY_ON2 = {
    '商品主数据.xlsx': {
        'left_on': '商品编号',
        'right_on': '商品编号',
        'how': 'left'
    },
    '门店主数据.xlsx': {
        'left_on': '门店编号',
        'right_on': '门店编号',
        'how': 'left'
    }
}
```

当数据来源或字段名称发生变化时，可以优先调整配置，而不是修改整个处理流程。

## 为什么采用模块化结构

项目没有将所有代码全部写在 `main.py` 中，而是进行了简单的职责划分：

```text
main.py
    ↓
业务流程

config.py
    ↓
配置和业务规则

excel_tools.py
    ↓
通用 Excel / Pandas 工具
```

这种结构能够减少：

- 重复代码
- 重复路径设置
- 业务代码与工具代码混杂
- 修改一个字段导致大量代码修改

同时也为后续继续扩展通用 Excel 自动化功能提供基础。

## 项目特点

### 1. 面向实际 Excel 业务场景

项目不是单纯进行 Pandas API 练习，而是围绕完整的数据处理流程进行开发。

### 2. 从一次性脚本向可复用代码发展

项目将重复出现的 Excel 操作逐渐抽取到 `excel_tools.py` 中，例如：

```text
文件读取
数据清洗
数据合并
去重
格式处理
```

形成相对独立的工具函数。

### 3. 配置与代码分离

将字段映射、合并规则等内容放入 `config.py`。

在需求发生变化时，可以减少对核心逻辑的修改。

### 4. 重视异常数据

程序不会简单地把所有异常数据直接删除。

对于重复、缺失、格式错误、匹配失败等情况，尽可能保留异常信息并输出异常报告。
